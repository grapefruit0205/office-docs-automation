# 프롬프트 기록 — AI를 어떻게 썼는가

면접에서 "AI를 어떻게 활용했나요?" 에 대한 근거 자료입니다. 결과물만 남기지 않고 **어디를 사람이 판단했는지**를 함께 적었습니다.

## 1. 사용한 요청(프롬프트) — 요지

| 순서 | 요청 | AI가 낸 것 | 사람이 판단한 것 |
|---|---|---|---|
| 1 | "점검 시스템 ①과 겹치지 않으면서 실무 서류(대장·계획서·보고서)를 자동으로 만드는 ② 포트폴리오를 설계해 줘" | 시트 10탭 데이터 모델, 문서 2종 레이아웃, 함수 목록, 4시간 구현 순서(S1~S9), 리스크, "버리는 순서" | 피벗 탭은 **선택 단계**로 내림(엑셀 내보내기와 충돌). 데이터는 전부 합성으로 고정 |
| 2 | "설계대로 구현해 줘" | `Code.js` / `양식.js` / `설치.js` / `설치_한번에.js` | 서식 도구는 ①에서 검증된 함수 재사용 |
| 3 | (내부) "구글에 올리기 전에 로컬에서 돌려 봐" | 구글 API를 흉내 낸 스텁 하네스로 설치→샘플→문서 40부→검증까지 실행 | 하네스가 잡은 버그 3건 수정(아래 표) |

## 2. AI 답을 그대로 쓰지 않은 부분

- **엑셀 호환**: AI가 처음 제안한 `ARRAYFORMULA`·`QUERY` 는 엑셀에 없습니다. 실무에서 대장은 엑셀로 넘어가므로 `COUNTIFS`·`IF`·`TEXT`·`MAXIFS`·`XLOOKUP` 만 쓰도록 제한했습니다.
  → 설계안의 "4. 핵심 구현 패턴"에 명시했고, 요약 2탭을 **본체**로 두고 피벗을 선택 단계로 내린 이유이기도 합니다.
- **6분 제한**: 무료 계정 1회 실행 제한을 설계에 반영해, 문서를 **8부씩** 나눠 만들고 시간이 초과되면 남은 건만 다음 실행으로 넘기게 했습니다. 중간에 실패해도 만든 문서가 날아가지 않습니다.
- **개인정보**: 지원자 메일 주소·실제 회사명·설비 태그를 코드에 넣지 않았습니다. 예제 회사명 `(주)가상케미칼`, 점검자 이름은 가상입니다.

## 3. 검증 방식 (사람 눈으로 40부를 읽지 않음)

1. **문서 대조 함수**: 원본 행의 모든 값이 문서 본문에 실제로 들어 있는지 문자열로 확인 → `대조 20부 / 누락 0건`(계획서 320항목 · 보고서 160항목)
2. **발행이력**: 만든 문서의 링크·소요 초·상태를 시트에 남겨, 누가 언제 무엇을 만들었는지 추적
3. **측정로그**: 자동/수작업 소요 시간을 같은 표에 쌓아 비교
4. **로컬 스텁 하네스**(개발용): Apps Script 런타임을 흉내 내어 `설치_전체 → 설치_샘플데이터 → 대장내보내기 → 문서 40부 → 합본 → 검증` 전 구간을 실행. 구글에 올리기 전에 오류를 잡았습니다.

## 4. 하네스가 잡은 오류 (수정 완료)

| 증상 | 원인 | 수정 |
|---|---|---|
| 발행이력의 `구글독스ID`·`PDF링크` 가 빈칸 | 코드가 `독스ID`·`pdf` 라는 짧은 이름으로 넘기는데 헤더는 `구글독스ID`·`PDF링크` 였음 | 넘길 때 별칭을 헤더 이름으로 변환 |
| 검증에서 `누락 40건` 으로 모든 작업계획서가 `오류` 로 바뀜 | 작업계획서 본문에 `상태`·`결재자` 를 넣지 않았는데 검증은 원본의 모든 열을 확인했음 | 문서에 `결재자`·`상태` 줄 추가(내용으로도 필요한 정보) |
| 상태만 `오류` 로 바꿨는데 문서 링크가 사라짐 | 발행이력 갱신이 줄 전체를 새로 덮어썼음 | 넘기지 않은 칸은 이전 값을 유지하도록 병합 방식으로 변경 |

## 5. 실제 구글 환경에서 발견해 고친 오류

로컬 하네스로는 잡히지 않고, 실제 Apps Script 에 올린 뒤 첫 실행에서 나타난 오류입니다.

| 증상 | 원인 | 수정 |
|---|---|---|
| 요약표의 이상률(BL-03 4.8%)과 보고서의 이상률(6.1%)이 달랐다 | 요약은 항목 9개 고정, 보고서는 그 설비에 해당 있는 항목만(측정값 `-` 제외) 분모로 썼다 | 요약의 분모를 `COUNTIFS(...,"<>-")` 로 바꿔 두 화면이 같은 정의를 쓰도록 통일 |
| 내부 함수(`_점검결과보고서작성`)를 직접 실행하면 `Cannot read properties of undefined` | 인수 없이 실행된 내부 함수 | 인수가 없으면 "메뉴 [서류자동화] → 점검결과보고서 일괄 생성 으로 실행하세요" 라고 안내하는 예외로 교체 |
| 내보낼 때 `Converting from application/vnd.google-apps.spreadsheet to ... is not supported` | `getAs(MimeType.MICROSOFT_EXCEL)` 로 시트를 xlsx 로 바꾸는 경로가 이 계정에서 막혔다(같은 코드가 다른 계정에서는 되는 경우도 있어 원인 파악이 어렵다) | `_내보내기()` 로 감싸 **①getAs → ②다운로드 URL(`/export?format=xlsx`, File > 다운로드 > Excel 과 같은 경로) → ③변환 실패 시 구글시트 사본을 출력 폴더에 보존** 3단계로 만들고, 어느 경로가 쓰였는지 로그에 남김. PDF·DOCX 도 같은 함수를 쓰도록 통일 |
| `점검대장 내보내기` 가 실패 | 내보낸 대장은 **임시 사본(다른 스프레드시트)** 인데, 드롭다운을 `requireValueInRange(설비마스터 범위)` 로 만들었다. 이 API 는 **같은 스프레드시트 안에서만** 범위 참조를 허용한다 | 설비태그 목록을 **값(문자열 배열)** 으로 읽어 `requireValueInList` 로 넣도록 변경. 하네스에도 이 제약을 흉내 내는 스텁을 넣어 재발을 막았다 |
| 설치·샘플 데이터가 수 분씩 걸림 | 수식 15,120개를 만드는 반복문 안에서 **행마다 `설정('조회함수')` 를 호출** — 호출마다 설정 탭을 다시 읽어 수만 번의 API 왕복이 발생 | 한 실행 안에서만 쓰는 메모리 캐시(`_설정캐시`, `_점검값()`), 값을 쓰면 그 키만 갱신. 문서 20부를 만들 때 점검기록 5,041행을 40번 읽던 것도 1번으로 줄임 |
| 설치 도중 `Exception: Service Spreadsheets timed out while accessing document with id ...` 로 멈춤 | 구글이 잠깐 응답하지 못하는 **일시적** 오류. 수식을 15,120개 쓴 직후·행을 지운 직후에 잘 난다(같은 코드가 다음 실행에서는 그냥 지나간다) | 무거운 호출(수식 쓰기·조건부 서식·값 굳히기·행 삭제)을 `_재시도()` 로 감싸 **1.5초·3초 쉬었다 최대 3회** 다시 시도. 재시도로도 안 되면 오류를 그대로 올려 원인을 숨기지 않는다. 실행 중 반복해서 읽던 설비마스터·작업계획도 한 번만 읽도록 캐시(같은 실행 안에서만). 하네스에 "설비마스터 읽기가 1회 타임아웃" 을 주입해 재시도가 실제로 넘어가는지 회귀 테스트 |
| 검증이 `대조 21부` — 20부를 만들었는데 21부로 셌다 | 발행이력에 같은 대상의 줄이 두 개(예전에 인수 없이 실행된 흔적). 중복 줄은 문서도 두 개로 세고, 그중 하나가 오류로 바뀌면 재생성이 반복된다 | `정리_발행이력중복()` 추가 — `문서종류`/`대상ID` 가 빈 줄을 지우고 같은 대상은 마지막 줄만 남김. `설치_전체` 가 자동으로 호출하고, `설치_확인` 은 완료 건수가 20을 넘으면 경고한다. 하네스에 중복을 주입해 42행 → 40행이 되는지 회귀 테스트 추가 |
| 첫 실행에 `ReferenceError: SH is not defined (설치.gs:103)` | `설치.js` 의 최상위 배열(`탭정의`)이 **로드 시점에** 다른 파일(`Code.js`)의 `SH` 를 참조. Apps Script 는 **파일 실행 순서를 보장하지 않아** `설치.js` 가 먼저 평가되면 터진다. 함수 안이 아니라 전역이라 실행 전에 이미 죽는다 | `탭정의` 를 함수(`탭정의()`)로 바꿔 **호출 시점에** 만들도록 수정. 하네스에 "최악 순서(설치.js 먼저)" 로드 시나리오를 추가해 회귀 검증 |

> 교훈: Apps Script 에서 **다른 파일의 값을 전역 선언에서 쓰면 안 된다.** 전역은 자기 파일 안에서만 완결되게 두고, 파일을 넘는 참조는 함수 안에서 한다(함수 선언은 순서와 무관하게 hoisting 된다).

## 6. 이 프로젝트에서 증명하는 것

- **자가 진단**: `설치_확인` 이 탭·헤더·행 수·수식·드롭다운·설정·폴더·발행이력을 12항목으로 검사해 ○/× 로 보여준다. 문제가 생기면 이 로그만 보면 원인이 잡힌다
- 시트 수식(COUNTIFS·XLOOKUP)과 스크립트를 **역할에 따라 나눠** 쓰는 감각
- 무료 계정의 **할당량·시간 제한**을 전제로 한 설계
- 만든 결과를 **기계적으로 검증**하는 습관(대조 함수·발행이력·측정로그)
- 합성 데이터로 실제와 같은 형태의 업무 산출물을 만드는 방법

## 7. 남은 개선 아이디어

- 피벗 탭을 항상 쓰려면 Sheets API 고급 서비스를 켠 상태를 전제로 하고, xlsx 에서는 별도 시트로 값을 굳혀 내보내기
- 문서 100부 이상: 트리거로 시간대를 나눠 자동 생성(현재는 메뉴 3회 실행)
- 승인 흐름: 결재란을 실제 도장 이미지·전자 서명으로 확장
